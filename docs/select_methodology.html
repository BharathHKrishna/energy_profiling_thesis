Why a select stage exists at all

BORE's discovered pool is a discovery ceiling, not a dataset to run the pipeline on directly — for strata with abundant real-world supply, BORE can find far more candidates than any downstream analysis needs. select is the step that turns "everything BORE found" into "the tier-balanced set the pipeline actually processes" — osm_carve and stream both operate on select's output, never on the raw pool.

Added 2026-08-10 — the pool→plan gap existed for a while before this stage was built (see project notes: "the actual selection script... not yet built").

The one dial: N_PER_STRATUM

Same dial drives both bore and select

run_pipeline.py's N_PER_STRATUM dict is read by both run_bore() (as a search quota fed to real_anchor_finder.py) and run_select() (as the exact per-stratum target count to sample). Set it to 1 for every stratum for a smoke test, or to the real production target plan for a full run — same code path either way, no separate config to keep in sync.

for stratum, target in dict(N_PER_STRATUM).items():
  pool = df[df["stratum_name"] == stratum]
  idx = sorted(rng.sample(range(len(pool)), target))
Changed 2026-08-10 from an earlier design that parsed target counts from docs/10000_coordinate_breakdown.html instead — that meant bumping N_PER_STRATUM for a smoke test didn't actually shrink what select drew, since it ignored the dial and always pulled the full HTML plan. Now there's exactly one source of truth.

Why a seeded random sample, not the first N rows

BORE's discovery order is not geographically representative — Phase 1 (chunked OSM discovery) processes continents/regions in a fixed sequence, Phase 2 (densify) clusters new points tightly around already-accepted anchors, and Phase 3 (GHSL seed) adds a third, different clustering pattern on top. Taking the first N rows in file order would systematically bias toward whichever phase/region happened to run first for that stratum, not a representative sample of everywhere BORE actually found real anchors.

rng = random.Random(RNG_SEED) # RNG_SEED = 555 (changed twice already this session: 42 → 777 → 555, each time to draw a genuinely different sample for a fresh smoke test)

Verified empirically, not just asserted: for one real run, the picked positional index within each stratum's pool ranged from 1 (Coastal + Agricultural, pool size 39) to 48,598 (Informal + Urban, pool size 58,007) — no clustering near index 0, confirming genuine spread rather than a first-row bug.

Measured performance

select is effectively instant regardless of scale — a single pandas filter + random.sample() call per stratum, no network/disk-heavy work. Every real run this session completed in <0.1 min, whether selecting 18, 16, or the 10,000-target production plan. It is not a cost driver for the 10k run — osm_carve and stream are (see their own methodology docs).
