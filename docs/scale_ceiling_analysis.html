BORE — Confirmed Real Results, Unified 3-Phase Method (revised 2026-08-10)

Supersedes the "Realistic Ceiling" estimates this section used to hold — those were projections before the method existed in runnable form. real_anchor_finder.py is a 3-phase search per stratum: Phase 1 chunked OSM discovery (continent-grid splitting, avoids single-query truncation), Phase 2 densify (7x7 grid tiling, 48 new points around every accepted anchor, for 10 strata whose real-world footprint is a large contiguous zone — Industrial, Dense Urban, Suburban, Industrial+Water, Urban+Coastal, Agrivoltaics, Industrial+Arid, Industrial+Forest, Suburban+Agricultural, Informal+Urban), Phase 3 GHSL Degree-of-Urbanisation seeding (Dense Urban, Suburban, Informal+Urban — satellite-measured urban centres, independent of OSM tagging, region-restricted for Suburban/Informal+Urban to match their Phase 1 scope — see caveat below). All three phases share the identical, unmodified ESA+GHSL gate — nothing below reflects a looser standard, only a wider search.

Two real bugs were found and fixed during the run that produced these numbers (2026-08-09), both documented in detail in project memory:
  1. Correctness bug: Phase 3's GHSL seeding for Informal+Urban initially searched globally with no geographic restriction — a live run confirmed false positives (Atlanta GA, Guangzhou China passed the built_up/height gate despite not being informal settlements). Fixed by restricting Phase 3 to the same regions Phase 1 already used for that stratum (and, caught proactively before it caused the same failure, for Suburban too — its gate has no bsurf requirement and Phase 1 deliberately excludes Africa for a documented ESA over-classification reason that Phase 3 needs to respect as well).
  2. Performance bug: running 6 strata concurrently (STRATUM_WORKERS=6) with per-candidate INFO-level logging caused severe lock contention on a single shared log file — a run stalled at 26+ hours for what should take single-digit hours. Fixed by reducing to STRATUM_WORKERS=1 (sequential, matching the originally-proven configuration) and launching with LOG_LEVEL=WARNING set.
With both fixes applied, the full run completed in 10h 56m 44s (≈0.16s/coordinate) — the numbers below are that confirmed result, not a projection.

Revised 2026-08-10: "Utility-scale Solar Farm" and "Airport / Aviation" removed entirely — a 100-sample-per-stratum visual review of real satellite imagery found both strata's classification rule produces a large fraction of non-matching results at scale (residential/farmland/water mislabeled as solar farms; generic suburbia mislabeled as airports). If pursued further (not implemented — needs real engineering, not just a bigger number):
Suburban → globalizing beyond the current 3 regions could plausibly reach five figures (place=town is genuinely abundant worldwide), but every new region needs its own pass-rate validation first — the existing 3 were chosen specifically because Africa was tested and rejected (ESA over-classifies small settlements there). Industrial / Industrial+Water could likely go beyond today's 8-10k, but only by splitting into regional sub-queries — a single unchunked global query above that range risks untested Overpass server-side truncation. Informal+Urban expanding to South Asia/Latin America and Dense Urban's place=city pass rate are both real open questions, not yet answered.
